# 改动影响分析

涉及持久化、跨语言协议、共享缓存或删除公开入口时使用。普通引用搜索只是起点。

1. 找出安全所依赖的一两条事实，例如“旧字段没有外部消费者”“这个清理只移除已过期记录”。
2. 沿真实调用方、固定依赖版本、序列化格式、数据库和生命周期核实；搜索无结果不能证明动态调用或外部契约不存在。
3. 用调用真实实现的测试、脚本或实际应用操作证明关键事实。已确认风险与已经排除的风险分开，未知写清缺少的证据。
4. 把证明加入回归检查；事实无法证明时保留契约或交付阻塞，不凭合理推断删除兼容行为。

交付：关键事实、依据、执行命令与输出、受影响调用方、未证明项。不罗列没有证据的泛泛风险。
