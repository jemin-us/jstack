# Playbook：visual

用于用户指定设计、截图或现有页面作为参照的视觉与交互工作。

1. **固定参照**：记录参照、页面、视口、语言、主题、字体和必要数据。取得实际浏览器截图，说明差异。把参照转成验收条目，逐项写"操作 → 期望"：结构、入口位置、搜索和筛选、空/加载/错误/有数据状态、可点击控件的鼠标反馈、键盘、窄屏。参照没有展示的项写"待确认"，不从图片推断。
   完成标准：比较双方的状态可复现，验收条目已列出；缺少必要参照时澄清，不能自行声称像素一致。
2. **实现**：按 [implement](../../../implement/SKILL.md) 在隔离 worktree 中修改，标明由 mode 派发后返回。按它第 3 步盘点 UI 体系后再动手，找共享布局根因；不靠裁剪、隐藏内容或改断点掩盖问题。
   完成标准：改动解释了观察到的差异，范围外行为保持。
3. **验证**：在约定视口和相邻关键尺寸比较截图及计算样式，逐条操作验收条目。浏览器工具不存在时标 BLOCKED，不用 lint 或静态截图生成替代真实操作。维护条目表，每行写当前 HEAD 下的结果：已验证（附证据）、未验证或受阻。
   完成标准：每个条目都有当前 HEAD 的结果，剩余差异明确列出。
4. **迭代**：用户在同一任务内追加反馈时，在原 worktree 和分支继续，把反馈补进条目表。只改样式、不改交互和数据的反馈，跳过 implement 第 1 步的验收检查 subagent，不新建 issue 或 worktree。重跑本轮 diff 影响到的条目，包括同一组件在其他状态和视口下的表现、鼠标反馈、键盘和窄屏；未重跑的受影响条目改回未验证。
   完成标准：条目表反映当前 HEAD，没有沿用被本轮改动影响的旧证据。
5. **交付**：将条目表和验证步骤交给 [finish](../../../finish/SKILL.md) 独立验证并交付 PR/CI；迭代轮次由 finish 只验收新 diff 并更新原 PR，用户追加反馈的轮次不计入 finish 的三轮修复上限。
   完成标准：报告视觉与功能结果，逐条列出未验证条目。
