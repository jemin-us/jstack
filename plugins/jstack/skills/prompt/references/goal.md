# `/goal` 条件

Claude Code 和 Codex 都支持 `/goal <条件>`：设定后 agent 连续工作多轮，直到条件满足，条件最长 4000 字符。两端的差异：

| | Claude Code | Codex |
|---|---|---|
| 谁判断完成 | 每轮结束后由一个小模型读对话判断。它不运行命令、不读文件，只认对话里出现过的输出 | 官方文档没有说明 |
| 什么时候停 | 评估模型判定条件已满足或不可能满足；或者出现必须由用户处理的错误；或者用户运行 `/goal clear` | 条件满足；或者 token 预算用完（`goals.max_goal_token_budget`）；或者用户运行 `/goal pause` 或 `/goal clear` |
| 前提 | 无人值守时要开 auto mode，否则工具调用仍会请求确认 | 要在 `~/.codex/config.toml` 里打开 `features.goals` |

写条件时逐条做到：

1. **每条检查先在当前环境跑一次。** 跑不起来的检查（缺依赖、缺配置、缺数据）不写进条件。在回复里告诉用户去掉了哪条、补上什么之后可以加回。跑不起来的检查永远不会通过，agent 会一直空转。
2. **写停止上限。** Claude Code 在条件末尾加"或者已经工作满 N 轮"，N 按工作量估计，没有依据时用 20。Codex 的上限由 `goals.max_goal_token_budget` 控制，没有配置时提醒用户。
3. **写受阻出口。** 两端都写"遇到需要用户决定的问题（改对外接口、删除数据、需求不明确）时停下，列出问题和各个选项"。
4. **Codex 要求按检查点推进。** 每完成一个检查点，输出一段简短进度：当前检查点、已经验证了什么、还剩什么、是否受阻。
