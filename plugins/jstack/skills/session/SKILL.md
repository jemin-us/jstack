# 任务暂停与恢复

## 流程

### 1. 定位本任务

仅使用当前对话、用户指定的交接文件、对应 PR/issue 和本任务工作区。不要扫描无关会话。用户要求暂停时完成第 2 步后停止；恢复时从第 3 步继续。没有明确任务对应关系时，先列出可确定的候选再澄清。

完成标准：目标、仓库及操作是暂停还是恢复已明确。

### 2. 保存交接

按 [references/handoff.md](references/handoff.md) 写交接记录，放在任务已有记录位置；没有时用临时文件并向用户给出绝对路径。写入前检查同名记录，不能覆盖其他任务。记录已完成和剩余步骤、base/HEAD、worktree、已提交和未提交文件、PR、证据路径与覆盖的 SHA、审查轮次、进程及其归属、下一步。不得保存密钥或认证内容。

先确认原始证据在清理后仍存在。停止本任务不再需要的进程；不停止共享实例，不丢弃未提交文件，不为暂停自行 stash、提交或创建 PR。暂停后不继续任务。

完成标准：接手者有明确继续位置，成果与证据可找到，进程状态已记录。

### 3. 核实与恢复

读取交接，核实 Git 状态、分支、worktree、PR HEAD 和证据是否存在。历史结论是线索；对应代码、输入或环境已变时，只重跑受影响的验证。无法取回的证据标为缺失，不沿用“已通过”的自述。保留用户后续修正，不重做已完成且证据仍有效的工作。

按 [mode](../mode/SKILL.md) 将剩余事项交回原流程，传入完整目标、约束、当前工作区、累计审查轮次及继续位置。工具不能恢复原 agent 时，新建执行者并传入这份记录；不假装后台进程还在运行。

完成标准：已说明继承了什么、哪些状态发生变化、从哪一步继续；原目标全部完成时直接交付，不新增工作。

## 示例

CI 仍在运行时用户要求暂停：保存 PR HEAD、已完成验收、CI 链接和下一步；停止本任务的本地 watcher。恢复时读取该 HEAD 的实际结果，只有新 push 才核对新增差异，不从实现阶段重来。

## 常见问题

worktree 已删除：先查保留分支、远端和未提交成果记录。已提交内容可恢复到新隔离工作区；未提交内容找不到时明确报告，不把旧汇报当作成果。
