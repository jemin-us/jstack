# 验证技能维护

目标是让功能清单、操作脚本和真实产品保持一致。范围限验证 skill、其自有脚本和证据说明，不改产品代码。

1. 定位现有验证 skill，对照路由、菜单、命令和功能文件检查遗漏、失效入口和重复项。没有目标时回到生成流程，不新造一张看似已有的清单。
2. 逐功能阅读相关源码并生成实际操作步骤，所有功能都进入覆盖表：功能、源码入口、操作、代码版本、结果、证据。清单很大时可以派只读 subagent 分析，实际操作由一个协调者管理实例，避免互相破坏状态。
3. 检查实例健康后逐功能实际操作；遇到异常先确认环境和状态，再继续。只能操作本任务拥有的进程或已明确允许使用的共享实例。证据保存到清理范围之外。
4. 分类处理：文档与实际正确行为不符是文档漂移；产品可用但脚本无法操作是工具缺口；实际产品违反契约是产品回归。前两类在本范围修复并重新操作验证；产品回归报告原始证据，不通过改文档或放宽断言掩盖。
5. 汇报 clean（所有功能有源码和实际覆盖，无需修改）、changed（有已验证的材料修复）、blocked（覆盖或修复交付受阻）。没跑到的功能写出具体前提，不能算 clean。
6. 有修改时按 [implement](../../implement/SKILL.md) 的提交与交接要求交付，已有工作区直接复用；将覆盖表和原始证据交给独立验收。无修改不创建空 PR。不要把产品问题修复混入验证材料 PR。

交付后确认本任务启动的临时进程已清理，证据仍在。报告各功能状态，不用“验证脚本跑通”概括未覆盖的产品行为。
