# 收尾

调用方传入 worktree 路径、分支、起点 commit、验收检查、累计审查轮次和实现汇报；传给 pr 的验收结论附完整 HEAD SHA。用户限定仅本地修改时，验收使用明确 diff，交付后保留未提交成果，不执行 PR 或清理。

## 流程

### 1. 独立验收与修复

读取 [accept](../accept/SKILL.md)，检查起点到当前 HEAD 的完整范围。FAIL 时由作者依据具体发现修复、重跑相关检查并提交，再交回独立验收；最多三轮，后续轮次只检查新 diff、未解决发现和受影响回归。BLOCKED 不盲目重试；用已有渠道能解决的环境问题先解决，否则保留现场并说明缺少什么。

完成标准：得到 PASS / PASS+NOTES；或三轮仍 FAIL、环境仍 BLOCKED，保留成果并报告，不进入正常交付。

### 2. 自动交付

验收通过后读取 [pr](../pr/SKILL.md)，自动 push、创建或更新 PR 并跟进 CI。把本 skill 路径、验收检查和起点传给 PR 流程；CI 修复产生代码改动时重新独立验收，累计审查轮数不重置。

完成标准：PR 对应当前 HEAD，CI 必过检查有确定结果；没有检查、未运行、等待和跳过分别报告，不算通过。

### 3. 清理与汇报

仅在独立验收通过、当前 HEAD 已推送，且 pr 返回 READY（或已核实 MERGED）后，按 [worktree](../worktree/SKILL.md) 清理 worktree、保留分支；失败或受阻时保留。默认停在可合并状态；本次明确要求合并时由 pr 执行并核实，发布状态按实际证据报告。

汇报三项：改了什么（含清理的旧路径及 PR）；验证了什么（作者自检、独立审查、当前 HEAD 的 CI 分别列出）；还有什么（受阻项、当前 HEAD 未验证的检查、未完成项、保留的路径和原因；用户确认结束不代替技术验收）。没有剩余事项写“无”。

完成标准：用户收到真实交付状态和 PR 链接，保留或清理的 worktree 与报告一致。

## 示例

局部样式修复完成后，独立验收确认浏览器效果；审查发现旧样式分支已无人调用，作者核实后删除，补跑检查并提交。第二轮检查新 diff 和受影响样式通过，自动 push、开 PR，等待 pr 确认 READY，再按收尾规则清理 worktree。

结果：交付 PR、浏览器证据、独立审查与 CI 结果，不要求用户逐步说“继续”。

## 常见问题

现象：验收需要的浏览器环境不可用。
处理：尝试项目已有的启动和验证方式；仍不可用时标 BLOCKED，保留分支和工作区，不把作者的静态自检替代独立验收。
