# 中文专项

用中文写给 agent 的文字时逐条检查。证据等级：实证（有公开评测数据）、厂商建议（模型厂商官方文档）、经验（实践总结，无对照实验）。依据和原始数据见 [中文指令写法调研](../../../docs/research/chinese-prompt-writing.md)。

## 1. 用结构或脚本控制长度

要控制长度时，规定结构（例如"三段：改了什么、验证了什么、还有什么"），或用脚本检查。精确字数、句数是中文下最难满足的约束，模型普遍写超长。

等级：实证（CFBench、LIFEBench）。

## 2. 命令、路径、标识符保留英文原文

技术术语、产品名、代码标识符、命令、路径、错误信息照原文写在中文句子里。中文夹英文术语不影响效果；反过来英文里夹中文略有下降。研究测的是理解任务，用在指令执行上属于外推。

等级：实证（ACL 2026 中英混排研究）。

## 3. 写明输出语言

需要中文输出时，在 skill、`CLAUDE.md` 或系统提示词里写明，不依赖模型推断。

等级：厂商建议（Anthropic 多语言文档）。

## 4. 中文写，不必改写成英文

没有证据表明把中文指令改写成英文会更好，结果随模型变化；"中文更省 token"也不成立。用团队最自然的语言写。

等级：实证，但证据弱（训练期实验、单篇小样本预印本）。

## 5. 同一概念始终用同一个词

一个概念选定一个中文词或英文术语后，全文只用它，不换同义词。这同时让它成为引导词，见 [principles.md](principles.md) 的"引导词"一节。

等级：经验。

## 6. 模糊量词换成可检查的条件

"适当""尽量""必要时"让 agent 自己定标准。改写成条件或数量，例如"超过 3 个文件时"。

等级：经验，没有中文专门的实证。
