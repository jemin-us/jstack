# 正文模板与常见写法

## 正文模板

````markdown
# <技能标题>

## 硬性规则
- 最关键的约束

## 流程

### 1. <第一步>
具体动作。
```bash
python3 scripts/<脚本>.py --input <文件>
```
完成标准：<成功时的状态>

### 2. <第二步>
……

## 示例
用户说：“新建一个营销活动”
执行：1. 查询已有活动；2. 按给定参数创建
结果：活动已创建，并返回链接

## 常见问题
现象：<错误信息>
原因：<为什么出现>
处理：<怎么修复>
````

## 先定方向

- **问题优先**：用户描述想要的结果，skill 负责决定调用哪些工具、按什么顺序调用。
- **工具优先**：用户已接入某个工具，skill 提供使用这个工具的最佳流程。

## 五种常见写法

| 写法 | 适用场景 | 关键做法 |
|---|---|---|
| 顺序流程 | 多个步骤必须按固定顺序执行 | 写明顺序和依赖；每步校验；写出失败后的回滚方式 |
| 多工具协同 | 流程跨多个服务或 MCP | 按阶段拆分；写明阶段之间传递的数据；进入下一阶段前先校验；集中处理错误 |
| 迭代打磨 | 产出需要多轮修改才能达标 | 写明质量标准；用脚本校验；循环修复；写明何时停止 |
| 按情况选工具 | 同一目标在不同情况下用不同工具 | 给出判断条件；写明备选方案；向用户说明选择原因 |
| 领域规则 | 除了调用工具，还需要专业判断 | 先检查后执行；用条件分支写清处理路径；留下审计记录 |

## 三类用途

1. **文档与产物生成**：内嵌风格规范，提供模板，交付前过一遍检查清单。
2. **流程自动化**：分步执行，每步设检查关口，形成迭代改进循环。
3. **MCP 增强**：串联多次调用，内嵌领域知识，处理常见调用错误。

## 让指令被执行

- 关键校验写成脚本。代码的结果是确定的，自然语言的理解不是。
- 关键约束用“关键：”开头，后面跟具体的检查项，不写泛泛要求。例如：

  ```
  关键：调用 create_project 前确认：
  - 项目名不为空
  - 至少指派一名成员
  - 开始日期不早于今天
  ```

- 模型跳步或草率时，可以补一句“不要跳过校验步骤”。这类提示写在用户提示词里，比写在 SKILL.md 里更有效。
