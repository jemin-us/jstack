# 写作规范

审查 skill 时逐句对照以下条目，列出违反的条目和所在行。每条标了证据等级：

- 实证：有公开评测数据支持。
- 厂商建议：模型厂商的官方文档这样建议。
- 经验：来自实践者的总结，没有对照实验。

前五条改写自 mattpocock/skills 的 [writing-for-agents](https://github.com/mattpocock/skills/blob/main/skills/productivity/writing-for-agents/SKILL.md)（MIT）。

## 1. 一处一义

每个意思只在一个地方写。重复会让它显得比实际更重要，修改时也容易漏改。要强调同一个概念，就重复同一个术语，而不是重复整句话。

等级：经验。

## 2. 不缓存环境里查得到的内容

一条命令或一个文件就能查到的事实，例如脚本列表、目录结构、`--help` 输出，让 agent 自己去查。正文只写查不到的内容：未成文的约定、决策的理由、配置里看不出的坑。

等级：经验。

## 3. 删掉 no-op 句子

模型默认就会做的事，写出来不改变行为，只占上下文。逐句问：删掉这句，行为会变吗？不会变就整句删掉。分歧靠实际运行判断。

等级：经验。

## 4. 把禁令改写成正向要求，写在执行点旁

写出要做的事，例如“注释写一行”。确实只能用禁令表达的硬约束，同时写出正向要求，并放在执行这一步的位置。

等级：经验。ReboundBench 观察到禁令会带出被禁内容，但只测了英文小模型，效应弱，参考价值有限（[来源](https://arxiv.org/pdf/2511.12381v1)）。

## 5. 每步有可检查的完成标准

每一步以完成标准结尾，让 agent 能分清做完和没做完。“已理解需求”这类模糊标准容易让 agent 提前结束这一步。要求越具体越彻底，例如“每个改动的模型都已列出”，agent 做得越完整。

等级：经验。

## 6. 用结构或脚本约束长度

控制长度时，规定结构，例如“三段：改了什么、验证了什么、还有什么”，或用脚本检查。中文下精确字数和句数是最难满足的约束，模型普遍写超长。

等级：实证（[CFBench](https://arxiv.org/html/2408.01122v2)、[LIFEBench](https://arxiv.org/pdf/2505.16234)）。

## 7. 中文正文保留英文的命令和标识符

命令、路径、代码标识符、产品名照原文写在中文句子里。研究显示中文夹英文术语不影响效果，反过来英文里夹中文略有下降。这项研究测的是理解任务，用在指令执行上属于外推。

等级：实证（[ACL 2026 中英混排研究](https://aclanthology.org/2026.acl-long.2080.pdf)）。

需要中文输出时，在 skill 里写明输出语言。

等级：厂商建议（[Anthropic 多语言文档](https://platform.claude.com/docs/en/build-with-claude/multilingual-support)）。
