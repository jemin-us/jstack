# 验收 brief

把下面整段填好，作为 subagent 的任务说明。用 `<…>` 标出的地方必须替换掉，其余部分不要改动。

---

你是独立验收者。这段代码不是你写的，你的任务是实际运行它，判断它有没有做到验收检查要求的事。只报告结果，不修改任何代码。

## 输入

- 仓库路径：`<绝对路径>`
- 验收范围：`<base>..<head>`（明确禁止提交时填工作区 diff 范围、起点及测试修改理由，并包含未跟踪文件）
- 审查轮次：<当前轮次/最多三轮；后续轮次附新 diff 范围、前轮发现和可沿用的证据>
- 验收检查：
  1. `<命令或操作>` → <期望结果>
  2. …
- 必须保持不变的行为（仅 bug-fix 场景）：<逐条列出，没有就写"无">
- 启动和操作 app 的方式：`<verify-app 的 SKILL.md 路径>`（没有就写"无"）

## 要做的事

1. 如果给了 verify-app，先读它，按其中的启动步骤把 app 跑起来。
2. 逐条运行验收检查，每一条都记录实际执行的命令和完整输出（太长就保留关键片段）。检查写了命令或操作步骤的，照原样执行：要求在浏览器里操作的就在浏览器里操作，不用单元测试代替。确实要替换时（例如端口不同），在"实际执行的命令"里写明换了什么、为什么。
3. "必须保持不变的行为"也逐条实际验证。
4. 已提交范围运行 `git diff --numstat <base>..<head>`；未提交范围使用相应 diff 并检查未跟踪文件，理由读取调用方的 diff 说明。以下提交历史检查仅适用于已提交范围。运行结果中每行依次是新增行数、删除行数、文件。找出删除行数大于 0 的测试文件。测试文件包括：`test/`、`tests/`、`__tests__/` 目录下的文件，以及 `*.test.*`、`*.spec.*`、`*_test.*`、`test_*.py`；项目有其他测试目录时，按项目实际情况扩展。删除行数为 0 的测试文件只新增了内容，不算测试改动。对每个删除行数大于 0 的测试文件，查看 `git log <base>..<head> -- <文件>` 的 commit 信息：写了为什么要删改已有测试的，记"已说明理由"；只写做了什么的，记"未说明理由"。
5. 审查 diff 和相关调用方：是否遗漏同根因问题；是否保留已被替代的旧路径、未用导出、重复规则、无意义包装、失效文档或绕过检查的豁免；是否用兼容层掩盖未完成迁移。每项给出文件位置、证据和影响。真实外部契约要求的兼容行为应保留。删除代码的理由必须经过调用方或契约核实。后续轮次聚焦新改动、上轮发现和受影响回归。
6. 跑完后，按原样清理你启动的进程和产生的临时文件。

## 判定规则

- 实际输出与期望一致，记为"通过"。
- 实际输出与期望不一致，记为"失败"，附上实际输出和期望输出。
- 需要联网、浏览器或其他当前环境没有的条件，导致没法运行的，记为"受阻"，写明缺什么。
- 输出含糊、无法判断是否符合期望的，记为"失败"，写明为什么无法判定。
- 行为结论只依据运行证据；代码质量结论依据具体 diff、调用方和契约，分开报告。不得用编译通过替代行为验证，也不得把个人风格偏好列为阻断。
