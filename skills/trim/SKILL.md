# 精简 agent 上下文

目标：每轮加载的内容只剩删掉后行为会变的句子，其余内容放在能按需加载的位置，并且有证据证明没有删过头。逐句怎么写、怎么修剪，按 [prompt](../prompt/SKILL.md)。

## 硬性规则

- 用户确认清单前不改任何文件。
- 先搬家再压缩：能整行搬到按需加载位置的整行搬，搬的时候不改写。不可逆操作的规则原样整段搬。
- 以下内容不删：用户的偏好、被否掉的方案和原因、机器环境；不报错的坑、看着像出错其实正常的现象；description 里“从不写入”“不上传”这类半句约束；删数据、花钱、发布、提权、改写已推送历史等不可逆操作的规则；规则台账和其他带日期的拍板记录。
- 改仓库外的文件（全局规则）前先备份改前副本；没有写权限时，把新版本写到临时目录，给用户替换命令。

## 放置位置

每块内容按下表放到能放的最高一级，越靠前越可靠：

| 内容 | 位置 |
|---|---|
| 能写成会失败的检查 | lint、测试或检查脚本；代码形状类交给 [codebase](../codebase/SKILL.md) |
| 同样输入总得同样输出 | 脚本或 hook |
| “做 Y 之前先读 X” | 做 Y 时由 hook 注入 X；客户端不支持时留一句指针 |
| 需要判断的流程 | skill 正文；只有部分场景用到的放进 `references/`，正文留一句何时读取 |
| 触发判断 | description，只写做什么、什么时候用、不用于什么 |
| 项目命令、发布步骤、对话里随时会触发的规则（提交、发布、回复、删除） | 项目指令文件（`AGENTS.md`）；挪进 `docs/` 的内容在指令文件里留一句什么时候去读 |
| 跨项目的硬约束和偏好 | 全局规则 |

两端差异：Claude Code 读 `CLAUDE.md` 和 `~/.claude/CLAUDE.md`，Codex 读 `AGENTS.md` 和 `~/.codex/AGENTS.md`。根目录已有 `AGENTS.md` 时不建 `CLAUDE.md`，否则 Claude Code 不再读 `AGENTS.md`。`when_to_use`、`paths:`、`.claude/rules` 和 hook 只在 Claude Code 生效，Codex 那端要保留文字版本。项目里重复全局规则的句子，只有用户用的每个客户端都读那条全局规则时才删。

## 规则台账

台账放在项目的 `docs/agent-rules.md`，指令文件里留一句“改 agent 规则时读 docs/agent-rules.md”。每行一条规则：

```markdown
| 规则 | 位置 | 由什么强制 | 出处 | 日期 |
|---|---|---|---|---|
| 生成文件不手改 | AGENTS.md | `make test` 漂移检查 | 仓库约定 | 2026-11-14 |
| 只有 mode 和 help 自动触发 | skills/*/SKILL.md | 仓库的 validate 脚本检查两端开关一致 | 用户拍板（选 2） | 2026-11-14 |
```

trim 下线一行时，写明理由：机制已经接管，或新模型实测不写也会照做。reflect 新增一行时，出处写用户纠正的原话或会话证据。

## 流程

### 1. 盘点

运行 `python3 <本 skill 目录>/scripts/inventory.py --project <项目> --skills <skill 根目录>`，得到每轮加载内容的字符数。再读按需加载的部分：各 skill 正文、`references/`、`docs/`。臃肿的内容先看是不是放错了位置，再看是不是写多了。

判断一个 skill 有没有人用，运行 `python3 <本 skill 目录>/scripts/usage.py <skill 名> ...`，它只认工具调用；按名字 grep 会话全文不算证据。调用 0 次的 skill 先查是否被其他 skill 按路径读取。

完成标准：每个每轮加载的来源都有字符数；每个 skill 都有调用数据，或写明没有记录。

### 2. 出清单

逐段给出处理方式：修、删、挪、改写、保留。挪写明目的地，每条附一句原因。

- 删：删掉后行为不变的句子，例如“先读再改”“跑测试”“注意边界”这类模型本来就会做的；步骤删掉后 agent 能换条路做到同样结果的。只有顺序本身是约束的步骤留下，例如先验证再发布、先确认再删除。拿不准的单列，交给用户定。
- 改写：同一种要求说了三遍，换成一个模型本来就懂的词，配一组 NO / OK 例子，例如“快、确定、开销小”写成“紧”，“要简洁”写成“不写报告腔”。
- 挪：按“放置位置”一节。description 里只有部分场景用到的内容移到正文或 `references/`。
- 修：指向不存在的文件、skill 或工具的内容，事实错误，两端不一致。

完成标准：清单覆盖第 1 步的每个来源；每条有处理方式和原因；要删除的 skill 和拿不准的条目单独列出。把清单交给用户，等用户确认。

### 3. 执行

按确认过的清单改。先搬家，再压缩，最后改写。改仓库外的文件前，把改前副本存到临时目录。改了 jstack 自己的 skill 时，运行仓库要求的生成和测试命令。

完成标准：清单每条都已执行，或写明没执行的原因；仓库的必过检查通过。

### 4. 核对消失的行

运行 `python3 <本 skill 目录>/scripts/vanished.py --git <起点 commit> --pair <改前副本> <改后文件>`，列出所有消失或被改掉的行。逐行对上清单里用户确认过的条目。新增了 `paths:` 时，确认每个 glob 至少匹配一个真实文件；拆走或改名的文件，grep 一遍旧文件名。

再派一个没参与精简的 subagent 查有没有删过头，派法按 [harness](../harness/SKILL.md)。brief 里只放消失的行清单和要搜索的位置，不放清单和你的结论；要求它对每行搜关键名词而不是整句，给出“仍在 / 部分在 / 找不到”和位置。

完成标准：每条消失的行都对上了确认过的条目；subagent 报告“找不到”或“部分在”、但不在确认清单里的行，已原样恢复。

### 5. 验证搬走的内容会被加载

每个新的加载位置各做一次：在新位置埋一个暗号，开一个新会话，先做一件会读到它的事再问暗号；再开一个新会话，读一个不该读到它的文件，做反向对照。验证完删掉暗号。

完成标准：每个新位置都有正向会话读出暗号、反向会话读不到暗号的记录；暗号已删除。

### 6. 交付

按 [harness](../harness/SKILL.md) 的三段汇报写。“改了什么”列出每轮加载字符数的前后对比；“还有什么”列出需要用户手动执行的命令和没验证的客户端。更新规则台账。

## 示例

用户说：“模型升级了，帮我把 jstack 的上下文再精简一遍。”

执行：inventory 得出每轮加载约 7.8k 字符，最大的是 Codex 全局规则 3.4k 和 18 个 description 共 2.4k；usage 显示 4 个 skill 调用 0 次；清单分 5 组，其中 4 条拿不准、交用户定；用户确认后先把三段汇报的定义从 6 个 skill 搬到 harness，再删重复；vanished 列出 53 行，独立 subagent 找出 1 行不在确认清单里，原样恢复；暗号埋在 harness，正向会话从 implement 第 8 步读到，反向读 brainstorm 读不到。

结果：每轮加载降到约 5.1k，台账多 2 行，汇报里附上 Codex 全局规则的替换命令。

## 常见问题

现象：新会话读不到暗号，但指针写得没问题。
原因：新会话没读 `--plugin-dir` 指定的源码，而是搜到了 `~/.claude/plugins/cache/` 里已安装的旧版本；禁用已安装插件也不一定够。
处理：在提示里写明要读的插件目录再测；测的是指针，不是插件安装。

现象：usage 显示每个 skill 都被用过十几次。
原因：按名字 grep 了会话全文；Codex 会把所有 skill 的路径注入每个会话。
处理：只用 usage.py 的结果，它只统计工具调用。

现象：读取 `~/.codex/AGENTS.md` 等仓库外文件被拒绝。
原因：当前权限只允许工作目录。
处理：不换方式绕过。用户之前已经给过内容时，基于那份内容在临时目录生成新版本，给出 `cp` 命令让用户执行。
