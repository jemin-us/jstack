# 写给 agent 的文字

目标是让 agent 每次按同一条路径执行，而不是每次产出同样的文字。skill、`CLAUDE.md`、`AGENTS.md`、brief 只是包装不同，写法相同。

写的是 Claude Code 或 Codex 的 `/goal` 条件时，先读 [references/goal.md](references/goal.md)，按它的四条写，再走下面的流程。

## 流程

### 1. 分清两类内容

把要写的内容分成步骤（agent 按顺序做的事）和参考（按需查阅的规则、定义、事实）。再判断每块内容是不是每条分支都要用：都要用的留在正文，只有部分分支用到的放进单独文件，用一句指针说明何时读取。

完成标准：每块内容都标了"步骤"或"参考"，并定好留在正文还是移出去。

### 2. 写指针和步骤

- 一直加载的指针（skill 的 description、`CLAUDE.md` 里指向某文档的一行）写清两件事：指向的是什么，哪些分支要读它。最能触发的词放在最前面，每条分支只写一个触发词。
- 每个步骤以完成标准结尾，标准要能分清做完和没做完，要求越具体越彻底。
- 用模型本来就熟悉的词承载一类行为，并在全文重复同一个词，不换同义词。

细节和例子见 [references/principles.md](references/principles.md)。写的是 skill 时，再读 [references/skill-mechanics.md](references/skill-mechanics.md) 决定调用方式和是否拆分。

完成标准：每个指针都写明了触发分支，每个步骤都有可检查的完成标准。

### 3. 逐句修剪

对每一句依次问：

1. 删掉这句，agent 的行为会变吗？不会变就整句删掉。
2. 这层意思在别处写过吗？写过就只保留一处。
3. 一条命令或一个文件就能查到吗？能查到就删掉，让 agent 自己查。
4. 是禁令吗？能改成正向要求就改；只能写禁令时，同时写出该做什么，并放在执行那一步旁边。

完成标准：剩下的每一句都改变行为、只出现一次、查不到，且尽量是正向表述。

### 4. 中文专项检查

用中文写时，读 [references/chinese.md](references/chinese.md) 并逐条检查。

完成标准：chinese.md 的每一条都已检查。

### 5. 交付

- 写作任务：交付文档，并列出移到单独文件的内容和对应指针。
- 审查任务：按"条目、所在行、问题、改法"列出违反之处，没有问题时说明已检查的条目。

## 示例

用户说："这份 AGENTS.md 有 400 行，agent 经常漏掉测试要求，帮我改一下。"

执行：把内容分成步骤和参考；发现测试要求埋在第 300 行的参考里，提到正文的步骤中并补上完成标准"`pnpm test` 全部通过"；把部署说明移到 `docs/deploy.md`，正文留一句"改动部署脚本时读取 docs/deploy.md"；逐句修剪，删掉"请认真仔细"这类 no-op 和重复的目录说明。

结果：正文 90 行，测试要求带完成标准写在步骤里，移出的 3 份文件各有一句指针。

## 常见问题

现象：agent 该读的文件没读。
原因：指针措辞太弱，没写出触发分支。
处理：先改指针措辞，写明在哪种情况下读；改了仍然不读，再把内容移回正文。

现象：agent 提前结束某一步。
原因：完成标准模糊，或后面的步骤太多分散了注意力。
处理：先把完成标准改成可检查的；仍然提前结束时，把后面的步骤拆到 subagent 或下一个 skill 里。
