# Playbook：perf

用于已测量的性能问题或用户给定的性能目标。先按 [worktree](../../../worktree/SKILL.md) 准备隔离工作区；没有性能症状的功能开发不走此流程。

1. **测量**：在相同输入、环境、预热和并发条件下记录基线、重复样本、错误率和原始 trace。分清端到端延迟与局部耗时，不能用更少工作量制造提速。
   完成标准：瓶颈与目标有测量依据；无法测量时报告 BLOCKED，不从源码猜收益。
2. **减少工作**：依次考虑删除无用工作、避免重复、减少频率、推迟执行，再考虑并发和更便宜的实现。跨边界变更先按 [architect](../../../architect/SKILL.md) 设计。
   完成标准：选定改动能解释基线中的瓶颈，并保持功能与错误契约。
3. **实现与复测**：调用 [implement](../../../implement/SKILL.md)，传入当前 worktree、目标和验收检查，标明由 mode 派发后返回。每个切片都以相同条件重测，报告分布、差值和噪声；无显著结论时写“不确定”，不算优化成功。
   完成标准：实际收益有原始数据可复查，行为回归通过。
4. **交付**：调用 [finish](../../../finish/SKILL.md)，传入行为检查和基线/修复后测量方法。PR 引用证据位置，不把一次最快值当整体收益。
   完成标准：独立者能复现测量方法，PR 与当前 HEAD 的 CI 状态已核实。
