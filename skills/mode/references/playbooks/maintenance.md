# Playbook：maintenance

适用于用户要求清理代码、定期重构或维护代码基线。执行本次维护，不隐式创建后台定时任务。用户只要审计时使用 codebase-audit 并结束。

## 步骤

1. **确定基线**：按 [worktree](../../../worktree/SKILL.md) 检查现状并建立隔离工作区，运行项目必过检查。范围取用户指定的模块；未指定时从现有基线和近期反复出现的问题中选择有证据的一组相关问题，说明范围，不默认重写全仓。
   完成标准：范围、起点和现有检查结果已记录。
2. **审计**：读取 [codebase-audit](../../../codebase-audit/SKILL.md)，在该范围内输出按根因组织的修法。维护流程已经包含后续实现，不停在建议清单。
   完成标准：每个修法有具体位置、保持不变的行为及验证方法。
3. **分批重构**：按依赖顺序将修法交给 [implement](../../../implement/SKILL.md)，传入当前 worktree、起点和验收检查，标明由 mode 派发、完成后返回。每批先确认行为测试通过，再迁移调用方、删除旧路径和失效示例；每批同步删除已经解决的基线条目，再运行项目检查并提交；基线收紧与代码修复同批完成，不等到下一步，不在不稳定基线上继续下一批。
   完成标准：所选问题已消除，原有行为保持，兼容行为都有实际契约依据。
4. **防止回归**：需要新增可机械检查的规则时调用 [codebase](../../../codebase/SKILL.md)，传入当前 worktree。移除已解决的基线条目，不扩大豁免或缩小扫描范围。需要语义判断的规则由审查验证，不硬凑检查脚本。
   完成标准：基线变化对应真实修复；新增检查有失败证明并接入现有 CI 命令。
5. **交付**：确认最后一批之后的检查、文档和基线修改也已验证并提交，然后读取 [finish](../../../finish/SKILL.md)，传入完整起点到 HEAD 的范围，执行独立审查、修复闭环和 PR/CI 跟进。
   完成标准：汇报清理的问题、基线前后数量、保持不变的行为、独立验收和 CI 结果；未完成项有具体原因。
