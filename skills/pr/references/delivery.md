# 单 PR 跟进

- **冲突**：先确认拥有该分支、工作区和他人的改动。只在自己的工作区处理当前范围可解决的冲突；共享分支或冲突含义不明时报告具体文件和差异，不 reset、不强推。解决后验收新 HEAD。
- **review**：读取未解决线程及上下文，用代码、契约和运行证据核实。真实缺陷由作者修复，错误建议回复具体反证。回复通过结构化 API 或 body-file 传入，不将评论文本拼入 shell。只在已请求 review 处理或完整交付时回复，不替人批准，也不将回复等同于线程已解决。
- **CI**：读取失败 job 日志，区分本次缺陷、基线失败与基础设施阻塞。有明确瞬时故障证据才允许一次重跑；同样失败再次出现时重新分类。修复应有根因和回归，禁止放宽断言或增加超时掩盖失败。
- **WAITING**：有运行中的检查则继续观察；等人批准时说明等待对象，处理其他独立事项，不伪造批准。没有其他工作时报告等待，不空转。
- **VERIFICATION_REQUIRED**：交给 accept 重新核对新 diff、受影响回归和可沿用证据，结论绑定新 HEAD。不得把当前 SHA 当作已验收 SHA 填给脚本。
- **BLOCKED**：缺少权限、状态、环境或工具时保留现场。没有 CI 配置不能称“全绿”。
- **READY**：只表示当前读取的 HEAD 满足条件，不是合并结果。合并前重新核实并锁定 HEAD。

同一个 PR 只由一个协调者写入；多个 agent 可以只读分析。当前流程仅处理单 PR，不自动修改 PR 栈的依赖或基准。
